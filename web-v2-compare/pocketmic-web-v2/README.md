# PocketMic LAN — website and launch kit v2

A complete static redesign of the supplied PocketMic Android / Windows website, plus audience landing pages, download and setup funnels, and social drafts. Product baseline: **PocketMic v0.1.4**, checked against GitHub on **9 September 2026**.

## Open it

**No build required:** open `pocketmic-preview.html` for a self-contained, navigable review of all pages. Its page picker and Back button are preview-only; they are not part of the deployable website. Internal links stay in the preview. GitHub, driver, support and donation links remain real external links. The preview has no microphone access.

For the actual multi-page site and social studio, use a local server. From Windows PowerShell:

```powershell
Set-Location 'B:\Temp\@Browser'
tar -xzf .\pocketmic-web-v2.tar.gz
Set-Location .\pocketmic-web-v2
py -m http.server 8080 --bind 127.0.0.1
```

Open `http://127.0.0.1:8080/site/` for the site, or `http://127.0.0.1:8080/marketing/social-studio.html` to review and copy the posts. Stop the server with Ctrl+C. Python is only needed for this local server or rebuilding; production is ordinary static hosting.

## Funnel structure

`Social post → matched audience page → both-app downloads → platform instructions → setup checklist → user-confirmed sound check → help / feedback`

Visitors can bypass the audience chooser and go directly to downloads. There is no email gate, invented trial, fake urgency, forced signup or automatic claim that a download worked.

The pages explain that the Android app and Windows receiver are both required, and that **VB-CABLE is a separate installation for routing into other applications**. The receiver sends to **CABLE Input**; the destination app selects **CABLE Output**.

## Rebuild and verify

Python 3.10+ is required for the authoring scripts. There is no package-install step for normal rebuilding:

```powershell
py .\src\build.py
py .\scripts\create_marketing.py
py .\scripts\render_social.py  # Optional: only when changing the artwork; requires Playwright
py .\scripts\build_preview.py
py .\scripts\verify_site.py
```

The delivered PNGs are already rendered, so skip `render_social.py` unless changing artwork. It uses the same local app captures, not generated replacement UI.

Optional browser verification, preferably in a dedicated virtual environment:

```powershell
py -m venv .venv
.\.venv\Scripts\python -m pip install playwright
.\.venv\Scripts\python -m playwright install chromium
.\.venv\Scripts\python .\scripts\browser_checks.py
```

Use that same virtual-environment Python for `render_social.py`. No activation or execution-policy bypass is necessary.

Edit page copy in `src/build.py`, styles in `src/site.css`, and behavior in `src/site.js`. Generated files in `site/` will be replaced when rebuilding. Rebuild the preview after any page changes. Graphic HTML is generated by `scripts/create_marketing.py`; edit that generator to keep changes reproducible.

## Before public launch

1. Deploy **only the contents of `site/`** to the existing `https://canopydigital.ca/sites/pocketmic-lan/` path. Do not deploy the review workspace, Python source, or verification folder as the public site.
2. Review the visibly labelled website-policy draft against actual hosting logs, retention and any injected scripts. This build removes the old Google Analytics, badge and donation-widget requests; it cannot control host-level injection.
3. Run one real Android + Windows + VB-CABLE + destination-app acceptance test. Confirm download hashes locally, permissions, signing prompts, pairing, sound, stop/reconnect and the intended app’s mic test. This package verifies the website, not native audio behavior.
4. Open the deployed routes and social-card images, then use the matched campaign URLs in the drafts. Nothing has been deployed, posted or scheduled by this work.

Release URLs and checksum values were checked against GitHub release metadata; native binary bytes were not downloaded or independently verified. Recheck the release before changing any button to a newer version.

## Measurement and privacy

The JS emits **local DOM events only**. There is no collector, dashboard, network analytics request, cookie or localStorage identifier. Checklist state is functional `sessionStorage`, written only after interaction. UTM values are restricted and carried in internal links, not stored by the site.

A download click is not an installation. `setup_self_reported` is a person’s confirmation, not device telemetry. See `docs/EVENTS.md` before adding any measurement adapter.
