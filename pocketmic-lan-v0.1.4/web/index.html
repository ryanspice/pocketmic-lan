01 — How it works

Seven steps, one LAN

Both devices stay on your private network. You type an IP and a pairing key; everything after that is encrypted.

  1. 1

    Start the receiver

    Extract PocketMicReceiver-win-x64.zip and run PocketMicReceiver.exe.

  2. 2

    Copy the receiver's IP

    Note the preferred IPv4 address the receiver shows.

  3. 3

    Enter the IP on the phone

    Type the same IPv4 address into PocketMic on Android.

  4. 4

    Enter the pairing key

    Type the same pairing key on both devices — it derives the AES-256-GCM key.

  5. 5

    Pick a Windows playback device

    Choose speakers or headphones for a local test, or CABLE Input for virtual-microphone routing into Discord, Teams, OBS, or games.

  6. 6

    Start the Windows receiver

    Press Start in the receiver — it waits for a short prebuffer before playback.

  7. 7

    Tap Start microphone on the phone

    PocketMic sends encrypted 10 ms UDP frames to your PC. End-to-end behaviour on physical devices is still pending validation — see Current limits.

02 — What is included

Two halves, one wire

A Kotlin transmitter on Android, a C# receiver on Windows, and a tightly-specified wire between them.

  • Android transmitter

    Kotlin with Jetpack Compose and a foreground microphone service.

  • Windows receiver

    C# on .NET 8 with WinForms and NAudio 2.3.

  • PCM16 over UDP

    48 kHz mono PCM16 in 10 ms UDP packets, 100 packets per second.

  • AES-256-GCM encryption

    Authenticated encryption on every datagram.

  • Two capture modes

    Clean and voice-processed microphone capture.

  • Adjustable gain

    Input gain and a live input level meter.

  • Selectable output

    Pick the Windows playback device, or route into CABLE Input.

  • Resilient streaming

    Prebuffering, bounded loss concealment, rollover-safe sequencing, and latency trimming.

  • Source fallback

    Audio source fallback tests actual recording startup before committing to a device source.

  • Build & verify tools

    PowerShell build, firewall, protocol, and source verification helpers.

03 — Performance profile

Measured and bounded — on real hardware

These numbers come from real-device testing on the owner's OnePlus 9 Pro and Windows 11 PC over 5 GHz Wi-Fi.

Prebuffer
100 ms

Windows waits before starting playback (adjustable 40–300 ms).

Latency trim
220 ms

Buffered latency trimmed above this high-water mark.

Concealment
200 ms

Maximum silence frames for short gaps (20 packets).

Raw bandwidth
768 kbit/s

48 kHz mono PCM16 — PCM costs more than Opus.

Wire format

  • 48,000 Hz mono signed PCM16, little-endian
  • 480 samples / 960 plaintext bytes per 10 ms packet, 100 packets per second
  • 768 kbit/s raw audio bandwidth; exactly 1000 bytes per datagram
  • Input meter updates at 10 Hz, not per packet
  • Android encryption, header, and packet buffers reused in the 100-packet-per-second hot path
  • Audio source is tested by actually starting a recording, with a fallback on failure

These settings are intentionally fixed until real-device measurements justify adaptive tuning.

05 — Build & install on Windows 11

From source to speaking

One-command PowerShell builds. The package ships source plus tooling — it does not pretend an APK or EXE was built in an environment without the SDKs.

Requirements

  • Android Studio with Android SDK Platform 36
  • Android Studio's bundled JBR, or another JDK 17+
  • .NET 8 SDK
  • Python 3 (optional — verification scripts)

One-command builds

# from the package root (PowerShell)
Set-ExecutionPolicy -Scope Process Bypass
.\scripts\build-android.ps1
.\scripts\publish-windows.ps1

Expected outputs

release\PocketMic-v0.1.4-debug.apk
release\PocketMicReceiver-win-x64.zip

Install the Android app

adb install -r .\release\PocketMic-v0.1.4-debug.apk

Firewall — private networks only

Allow the selected UDP port on Private networks only. Default port: 49500.

.\scripts\allow-firewall.ps1
.\scripts\allow-firewall.ps1 -Port 49501

Route into Discord, Teams, OBS, or a game

  1. Install VB-Audio VB-CABLE
  2. Select CABLE Input in the PocketMic Receiver
  3. Select CABLE Output as the microphone in the target application

06 — Current limits

Honest, on purpose

None of these are hidden before you build.

  • Windows receiver only
  • LAN discovery with manual IPv4 fallback; no QR pairing
  • PCM uses more bandwidth than Opus
  • Fixed prebuffer and simple latency trimming, not adaptive jitter or clock recovery
  • No signed Android release, no Windows installer, no updater
  • End-to-end behaviour still needs physical Android, Windows, Wi-Fi, and VB-CABLE testing
