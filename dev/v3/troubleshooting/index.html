The phone will not connect.

Check that both apps use the same release, both devices share a trusted private network, and the IP address, port, and pairing key match. QR pairing reduces manual entry errors.

Guest-network isolation, VPN routing, or a managed network may block device-to-device traffic. Check network configuration rather than disabling security tools. Use the project’s documented Private-network firewall rules.

See the network and firewall notes.

The phone’s input meter does not move.

Confirm microphone permission is granted to PocketMic and the microphone is started. Check whether another app is using the microphone. Stop and restart capture, then test the available capture modes one at a time.

Do not interpret a successful QR scan as proof of microphone capture.

The phone meter moves, but receiver packets do not.

Confirm the receiver is running and listening on the expected port. Recheck the PC address and pairing key. Review any receiver rejection messages. Return to the local-network and firewall checks if no packets arrive.

The receiver has audio, but my app hears nothing.

Select CABLE Input as the receiver’s playback destination. In the destination app select CABLE Output as the microphone. If the endpoint was renamed, match the VB-CABLE playback and recording sides.

If the cable devices do not appear, finish the official VB-CABLE installation and restart steps (opens in a new tab). Reopen the destination app after the driver installation. Also check the app’s mute state and Windows microphone-access settings.

I hear echo, doubling, or feedback.

Turn off the receiver’s speaker-monitoring option when it is not needed. Use headphones for the listening output. In OBS, make sure the same audio device is not captured both globally and as a scene source.

Check one signal path at a time instead of stacking monitoring, loopback, and call playback.

The sound is late, unstable, or cuts out.

A 10 ms packet is not a 10 ms end-to-end path. Network conditions, device capture, receiver buffering, and Windows audio routing all contribute.

Test close to the access point and try a wired PC where practical. Observe loss and buffer diagnostics. Adjust the receiver prebuffer carefully: less buffering can reduce delay but leave less room for late packets. Review OBS sync in a recording rather than judging it from a moving meter.

The installation looks wrong or is blocked.

Stop and confirm the exact source, file name, version, and checksum. The Android consumer download is the debug-signed APK, not the unsigned release artifact. The Windows receiver is a ZIP to extract, not an installer.

Do not disable Play Protect, antivirus, or the firewall to force installation. On a managed device, follow your organisation’s installation policy. Return to verified download details.

Never fix routing with a public port.

PocketMic is intended for a trusted private LAN. Do not expose the receiver to the internet or switch off the firewall.

Still stuck?

Report the app version, device models, destination app, symptom, and the last point in the signal path that worked. Remove pairing keys, QR codes, and sensitive connection details first.
