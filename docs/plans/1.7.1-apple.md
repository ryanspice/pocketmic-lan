# 1.7.1 Apple development delivery

Status: planned; physical acceptance outstanding. Reconciled 2026-10-15 from the [1.7.0 baseline](../releases/1.7.0/release.md). This plan does not bump versions or authorize store publication.

## Objective and existing implementation

Make the existing Apple previews reproducible for testers and verify real phone-to-desktop audio. The [iOS workflow](../../.github/workflows/ios.yml) already builds/tests simulator applications on ordinary source events and creates unsigned archives on tags/releases. The [macOS workflow](../../.github/workflows/macos.yml) already builds/tests a universal unsigned app and Audio Server Plug-in driver, packages notices/install/recovery files and validates artifacts.

Current compatibility is PCM v1 and manual pairing on Apple. Mac Opus decoding, iOS QR pairing, Mac discovery, multiple consumers and a background Mac service are outside this bounded pass unless a reproduced blocker requires a scoped decision. Windows retains PCM/Opus and the accepted modern/classic desktop behaviour.

## Sequence and exit criteria

1. **Choose an exact candidate and tester environment.** Record commit, workflow run, build versions, artifact hashes, device/OS versions and codecs. Rebuild expiring CI artifacts when necessary; an expired URL is not an application defect. Review [Mac instructions](../../macos/README.md) and preserve the version/locale/package validators.
2. **Run deterministic checks.** Pass the existing Android/Windows and Apple protocol fixtures, platform tests/builds, locale checks and exact Mac artifact verification on the candidate. Check iOS archive identity/version as part of artifact review; add automation only if the existing checks leave a demonstrated gap.
3. **Verify physical interoperability.** Exercise Android-to-Mac, iPhone-to-Windows and iPhone-to-Mac PCM audio, and retain Android-to-Windows regression coverage. Cover permissions, matching/wrong keys, audible destination-app input, repeated start/stop, network loss/recovery and sustained sessions. Verify the Mac's Opus incompatibility warning instead of claiming Opus support. Record duration and measured latency only when actually measured.
4. **Verify the Mac driver lifecycle.** Check installation, CoreAudio registration, selected-app input, underrun/disconnect behaviour, guarded uninstall and recovery using the [tester report](../../macos/TESTER-REPORT.md). Do not change system security policy to force unsigned artifacts to load; record an OS refusal as a blocker. The current driver is an Audio Server Plug-in, not a DriverKit extension.
5. **Decide distribution and localization scope.** Choose whether this candidate remains an unsigned development delivery or adds signing/notarization/provisioning. Implement credentials only through the chosen private configuration workflow; existing CI does not sign or upload to TestFlight. Claim only locales that have the required fluent and layout review.
6. **Prepare the release when the scoped gates pass.** Align version/build metadata, docs and artifacts; run the frozen candidate workflows; record checksums, known limits and device receipts. Publish only within the owner's release authorization and reverify the uploaded assets. Preserve 1.7.0 as its own immutable release.

## Decisions and blockers to record

- Available physical iPhone/Mac hardware and tester ownership.
- Unsigned tester delivery versus a separately scoped signed distribution path.
- Any OS/driver refusal, reproducible protocol/routing defect or unsupported locale.
- Which physical scenarios remain unrun and whether they narrow the release claims.

Signing/store delivery, new codecs, new transports and a broad UI rewrite are not prerequisites to obtaining honest development-test evidence. Conversely, successful CI cannot substitute for the physical tests listed here.
